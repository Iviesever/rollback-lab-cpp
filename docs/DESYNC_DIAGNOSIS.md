# Desync Diagnosis

A prediction mismatch is temporary and expected. A desync is a mismatch between hashes for the same confirmed canonical boundary. Packets carry up to 32 increasing confirmed hashes. The tracker requires both observations to be confirmed and to name the same frame before it can emit a diagnostic.

The first diagnostic records:

- earliest divergent boundary;
- local and remote FNV-1a hashes;
- up to 32 recent confirmed input pairs;
- both players' position, HP, and score;
- active projectile count;
- simulation and protocol versions;
- scenario seed.

Later differences do not overwrite an earlier frame. The state summary comes from the detecting peer's exact tagged snapshot at that boundary, and recent inputs come from that peer's own confirmed history—not harness truth. Hashes are deterministic identifiers, not cryptographic proof, security authentication, or cheat detection.

## Controlled injection

`SimulationVariant::damage_bias` adds exactly one damage point in a deliberately separate, opt-in path. The default canonical variant never reads test state. The regression scenario positions the players so frame 0 attack collides immediately:

```text
boundary 0: equal initial states
frame 0: same confirmed input pair
boundary 1: canonical damage 25, injected damage 26
diagnostic: earliest_divergent_frame = 1
```

With the remote observation flagged unconfirmed, no diagnostic is emitted. Marking both observations confirmed records frame 1.

Generate the checked production diagnostic with:

```powershell
build\msvc-debug\rollback_lab.exe desync-demo --out artifacts\desync.json
```

The checked-in [sample diagnostic](../samples/desync-diagnostic.json) is generated by the real UDP injected-fault command and reports earliest boundary 91 with 32 preceding confirmed input pairs.
