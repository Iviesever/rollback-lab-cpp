# Engine presentation boundary

The SDK owns canonical player/projectile positions, velocities, HP, score, input history, predictions, snapshots, rollback decisions and hashes. UE owns key sampling, the external wall-clock accumulator, geometry, camera and HUD state.

```text
UE keys -> bounded button bits -> C ABI live step
                                      ↓
                       Existing Core sessions and packets
                                      ↓
                    Copied snapshots and correction results
                                      ↓
                       UE transforms, geometry and HUD
```

An Actor transform is a projection of integer coordinates. It is never simulation authority. Moving a visual object, changing camera projection or fading a correction ghost must not write position/velocity back to an SDK session. Rendering can use float/double; the canonical C++ state remains integer-only at 1/1,024-world-unit scale.

## Two worlds and one scene

The two visible arenas read two different session handles. Each handle owns its own canonical world, input history, snapshots and rollback decisions. The two worlds are displayed in one Unreal scene; they are not two UE Replication clients. The production live driver transfers versioned packets between the sessions. It cannot copy one canonical state into the other to make their hashes match.

Isolation is tested at several levels: advancing A leaves B unchanged, wrong/shared/used session pairs are rejected, session hashes and history are checked independently, and UE verifies distinct handles with real prediction and correction. Handle addresses are process-local diagnostics and do not enter scenario, replay, trace or report identity.

The native presentation Actor creates a fixed pool of two floor components, four player components and 128 projectile components, six shared material instances and one camera. Projectile visual slots are reused. The HUD uses a cached view reference instead of searching the world each tick. Map and material are generated by repository code, without manually placed Actors or Blueprint setup.

## Correction and desync

Correction presentation consumes a real SDK correction's copied before/after worlds, earliest frame and resimulation depth. Its revision advances only after an actual correction. The renderer retains that event for a transient ghost, line and flash. Multiple corrections during catch-up still execute canonically; the display can show the most recently observed event while metrics/trace retain the actual run history.

A predicted difference concerns an unconfirmed state and is normal under latency. A desync is a hash mismatch for the same confirmed boundary. The controlled damage-bias demonstration reports the earliest confirmed divergent frame; it does not label normal prediction differences as failures.

Rollback replaces canonical effects by restoring and resimulating, rather than appending duplicate gameplay damage/projectiles. A production audio/VFX system would additionally need stable event identity and reconciliation. This demo's correction indicators are bounded presentation; it does not implement a general production event-reconciliation framework.

## Ownership on exit

The presentation Actor, `ARollbackArenaView`, stops its run and unregisters capture callbacks at EndPlay. The game-instance subsystem deinitializes the native Runtime; module pre-exit/shutdown stops registered runtimes. Native ownership destroys the borrowing driver, then both session handles inside the SDK, then releases the final DLL reference. Reset clears transient input and correction display state. Actor destruction cannot leave an SDK handle calling an unloaded library.

The same scripted inputs and transport seeds pass through CLI, C ABI and UE. Their final report/hash and replay comparisons constrain the claim that there is one shared implementation path. Equal hashes do not prove collision freedom or absence of a shared bug. Golden sample bytes, compiler parity, canonical replay reconstruction, negative tests and ownership review add independent constraints. Final packaged proof is identified in the [verification matrix](../tasks/20260904-100800-ue5-live-integration-0.2/verification_matrix.md) and generated verifier JSON.
